The Batch：Kimi K3 架构突破，scaling 效率约为 K2 的 2.5 倍
The Batch / Moonshot2026-07 · 权重 7/27 开放7天高频信号

The Batch 解读 Moonshot Kimi K3（2.8T MoE、104B 激活、1M context）：架构引入 Kimi Delta Attention（KDA 线性注意力）与 Attention Residuals，显著改善长序列与深层信息流动，scaling 效率约为前代 K2 的 2.5 倍，能力仅次于 GPT-5.6 Sol 与 Claude 5 Fable。全量权重已于昨日（7/27）开放，API 定价 $3/$15 每百万 token，编程场景经缓存可使有效输入成本降至约 $0.3。

💬 点评

K3 的看点不只是「最大开源 MoE」，而是「架构效率 + 缓存定价」双降本——它把「私有化能不能用得起最强档」这道题真正打开了。

🎯 业务视角

对企业解决方案客户，K3 让「长文档 / 整仓代码一次喂入」的私有化 POC 变得现实；鞋服电商侧可评估用它做长周期客服会话、商品长文案与多 SKU 详情批处理，先按缓存定价小流量验证 ROI 再谈规模化。

🔬 技术背景

KDA 线性注意力压低 1M 上下文的推理开销，Attention Residuals 缓解深层信息衰减；2.8T MoE 稀疏激活（104B）是「大参数、可控推理成本」的关键，缓存计费对编程类高重复前缀尤其友好。

🔗 上下游影响

利好长上下文推理引擎、KV Cache / 缓存计费、私有化交付与量化工具链；对只做闭源 API 的中间层是压力，对「多模型路由 + 自托管」方案是利好。

arXiv《Regression Tax》：为 Agent 加技能，既提升又损害表现
arXiv cs.AI2026-07-24 · 2607.225207天高频信号

《Regression Tax: Deconstructing How Skills Both Help and Hurt LLM Agents》通过 6000+ 次运行量化了一个反直觉现象：为 Agent 添加新技能虽然平均提升成功率，却常常让原本能解决的任务失败（即「回归」）。研究揭示「技能描述渗透」等三大回归成因，对提升 Agent 稳定性极具指导意义。

💬 点评

这是把「Agent 越加工具越不稳」的工程直觉变成了可测量的「回归税」——比任何能力跑分都更贴近生产落地的真实痛点。

🎯 业务视角

对做 Agent 交付的团队是「避坑清单」：新增工具 / 技能要做回归测试，保留「基线成功集」防止老任务被拖垮；鞋服电商的运营 Agent 上线新技能前应跑固定验收集。

🔬 技术背景
