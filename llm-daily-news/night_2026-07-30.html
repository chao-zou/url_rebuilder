#01
MCP 无状态规范 D+2「收盘复盘」：Claude / AWS 落地生态，HCSEC-2026-23 把「无状态化安全债务」摆上台面
工具互操作 / MCP官方 blog · Claude · AWS AgentCore · HashiCorp HCSEC-2026-23 · 07-28📈 30天持续趋势

MCP 2026-07-28 规范是问世以来最大修订：协议层不再维护会话状态，移除 initialize/initialized 握手与 Mcp-Session-Id，协议版本 / 客户端身份 / 能力声明改由每次请求自带的 _meta 承载，新增 Multi Round-Trip Requests、header-based routing（Mcp-Method / Mcp-Name）、可缓存 list 结果、Extensions 框架（MCP Apps + Tasks）、authorization 加固与 Tier-1 SDK。D+2 内 Claude、AWS Bedrock AgentCore Gateway（一次 UpdateGateway 即启用）相继落地；但同日 HashiCorp 披露 HCSEC-2026-23——Terraform MCP Server 在 stateless HTTP 模式下 per-session 凭证缓存失效、A 租户凭证被 B 租户复用，成为无状态化后的首个「协议范式切换引入的安全事件」样本。

💬 点评

今晨我们把这条定位为「生态落地日」，今晚收盘看到的是硬币的另一面：无状态化把「状态与安全由协议兜底」的旧模型拆掉，收益是可跑在 serverless / edge、可缓存、易扩展；代价是「谁来隔离、谁来鉴权、谁来审计」被下放给了实现方。HCSEC-2026-23 不是 MCP 协议漏洞，而是「按旧的有状态假设写的 server，在无状态模式下 per-session 缓存直接失效」——这恰恰是范式切换最典型的坑。Tigera 说得直白：六个 OAuth SEP 只硬化了 client→server 认证，Agent 身份 / 逐请求授权 / 委托 / 审计仍在协议之外，「still sit with you」。

🎯 业务视角

对企业方案商：给客户接 MCP 工具网关时，务必确认 server 是否显式启用 stateless HTTP 模式，并把「多租户凭证隔离、逐请求鉴权、调用审计」写进交付 checklist，而不是假设协议兜底；鞋服电商的导购 / 客服 / 商品库 Agent 若通过 MCP 接私有工具（库存、价格、订单），要按「每次请求都可能落在不同实例」重新设计凭证与租户隔离，避免跨品牌 / 跨门店数据串号。给 CIO 的话术：无状态 MCP 降的是运维和扩展成本，抬高的是安全治理责任，二者要同时上预算。

🔬 技术背景

无状态核心把 initialize 握手与 Mcp-Session-Id 删掉，每个 tool call 变成自包含 HTTP 请求，任意 server 实例都能处理；这直接破坏了「按 session 缓存凭证 / 客户端」这类实现假设。HCSEC-2026-23 的根因就是 per-session Terraform client cache 用 session id 区分用户，无状态模式下无法正确隔离。缓解手段：改为逐请求携带并校验凭证、按租户维度隔离缓存键、在网关层做 Mcp-Method/Mcp-Name 路由 + 授权。

🔗 上下游影响

上游是协议标准（Anthropic 主导 + 社区 SEP）与云厂商网关（AWS AgentCore、Netlify、Zoom 等）；下游是所有把 MCP 当「Agent 的 USB-C」的应用与 server 生态。这条与本期第 4 条（computer-use 感知安全）是同一母题：Agent 能力越往「能动手 / 能联外部工具」走，攻击面就越从「模型输出」转移到「工具调用与环境感知」，安全需要从协议层下沉到实现层。

🚀 6个月产品卖点预测

未来 6 个月，预计会出现「MCP 安全网关」这一细分品类：把逐请求鉴权、多租户凭证隔离、调用审计、异常检测打包成中间层，卖点是「无状态省成本、网关补安全」；面向企业的 Agent 平台会默认提供「stateless MCP 合规接入模板」，并把 HCSEC-2026-23 作为反面案例写进最佳实践。

Kimi K3 开放权重 D+3「经济性收盘」：AA Index 57 领跑开源，但 $3/$15 + 单任务约 $0.94 落在 Sonnet 档
开源前沿 / Moonshot AIArtificial Analysis · OpenRouter · 36Kr · 07-28🔥 7天高频信号

Kimi K3（2.8T MoE / 1.05M context / 原生多模态）在 Artificial Analysis Intelligence Index 拿到约 57 分，领跑所有开源模型，前面仅 Fable 5（~60）、GPT-5.6 Sol（~59）、Opus 4.8（~56）三家闭源。但定价并不「白菜」：OpenRouter / 官方口径 $3/M 输入 + $15/M 输出、cache-hit $0.30（-90%）、单任务平均约 $0.94（36Kr）——与 Claude Sonnet 同档，而非外界默认的 sub-dollar 中国模型档。The Batch 指出其 Kimi Delta Attention + Attention Residuals 带来约 2.5x 于 K2 的 scaling 效率。

💬 点评

🎯 业务视角

四层 RAG = 在朴素检索之上叠加改写 / 重排 / 去噪 / 归因等层次；MemGate「记忆闸门」= 对写入 / 读取记忆做门控，避免噪声记忆污染长会话；这与近期 arXiv 记忆归因、检索去噪的研究母题一致：信息不是越多越好，用得对才好。

🔗 上下游影响

上游是协议标准与开源工程实践；下游是所有做企业 AI 客服 / 导购 / 内部 copilot 的团队。播客把第 1 条（协议 / 安全）、第 7 条（工程骨架）落到「客服 / 导购」这个鞋服电商最高频的场景，形成闭环。

🚀 6个月产品卖点预测

未来 6 个月，预计「记忆闸门 + 分层 RAG + 协议选型」会成为企业 AI 客服 / 导购的标准工程模板；面向非技术业务方的「开箱即用 Agent 入口」会快速普及，AI 工具破圈从个人生产力走向部门级标配。
