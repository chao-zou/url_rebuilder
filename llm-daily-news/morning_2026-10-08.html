Cross-Tokenizer On-Policy Distillation：跨 tokenizer 蒸馏开始从“对齐覆盖”转向“监督可靠性”

💬 点评：多模型、多 tokenizer 混用越来越常见，蒸馏链路的稳定性比单次 benchmark 更关键。

🎯 业务视角：企业若要把大模型能力迁移到小模型/私有模型，需要评估数据映射、teacher 信号可信度和上线后漂移。

技术背景：On-policy distillation 关注 student 在自身分布下学习 teacher 行为，跨 tokenizer 会放大 token 对齐误差。

🔗 上下游影响：上游影响训练数据管线与 tokenizer 选择；下游影响模型压缩、端侧部署与行业小模型复制。

TRACE：面向 MoE Language Models 的 FP4 Quantization-Aware RL

💬 点评：低比特推理从“压缩模型”进一步进入“训练/RL 阶段就考虑低精度”的系统优化。

🎯 业务视角：如果 FP4 + MoE RL 路线成熟，私有化部署的 GPU 成本、吞吐和延迟都会出现新优化空间。

技术背景：Quantization-Aware Training 在训练中模拟量化误差，避免部署时精度突然掉线；MoE 则通过稀疏激活提升单位计算效率。

🔗 上下游影响：上游带动低精度 kernel、量化训练框架；下游影响客服 Agent、代码 Agent 的单位 Token 成本。

🚀 6个月产品卖点预测：低精度 RL 微调、成本可视化、按场景推荐 FP4/INT8/BF16 推理策略。

HuggingFace Daily Papers

From Evidence to Action：Tool-Using Agents 的失败点转向“证据到动作”的桥接

💬 点评：Agent 出错不只因为不会检索，也可能因为拿到证据后没能转成正确动作。

🎯 业务视角：企业 Agent 评测应覆盖证据选择、工具调用参数、动作顺序和回滚策略，而不是只看最终答案。

技术背景：Tool-using Agent 的链路包含信息检索、规划、工具选择、参数生成、执行和验证，任何一环都可能造成连锁错误。

🔗 上下游影响：上游需要更可追踪的工具日志；下游需要把 Agent 评估和 APM/审计系统打通。

🚀 6个月产品卖点预测：Agent trace replay、失败归因、自动生成 SOP 修复建议会成为企业 Agent 平台关键模块。

原文链接：HuggingFace Paper · arXiv
