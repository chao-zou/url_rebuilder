Kimi K3 持续发酵：2.8T 开源 MoE 在 Arena 前端代码榜超越 Claude Fable 5 与 GPT-5.6 Sol

💬 点评

Moonshot 用 Modified MIT 把一个 2.8T、1M 上下文、原生视觉的 MoE 真正开放出来，并且在 LMArena Frontend Code Arena 以 1679 Elo 拿下第一（Claude Fable 5 为 1631，GPT-5.6 Sol 为 1618），这是国产模型第一次在该盲评榜登顶。Artificial Analysis Intelligence Index 57，全球第四、开源第一；价格 $3 / $15 per M tokens（cache miss / output），是同档闭源旗舰的 1/3–1/5。

🎯 业务视角

对鞋服电商这类有大量前端/营销素材/活动页快速生成需求的客户，K3 提供了一个“私有部署可用 + 前端代码能力强 + 长上下文”的选项，可作为火山引擎 Agent Kit 之外的 fallback，用于私有化 POC 与多模型路由层。

🛠 技术背景

架构为 896 专家的大规模 MoE，激活参数约 20B+；推理需 64+ 加速器，官方推荐 vLLM / SGLang / TokenSpeed，已支持昇腾 950 全系列与 Atlas A3 大 EP 部署；Kimi API 原生 OpenAI 兼容。

🔗 上下游影响

上游拉动昇腾/国产算力与 vLLM/SGLang 生态；下游推动“开放权重 = 企业级基础设施”从口号变成采购清单，并对闭源旗舰的 coding 单价形成持续压制。

🚀 6 个月产品卖点预测

6 个月内：(1) 主流云厂会把 K3 纳入托管推理 SKU；(2) 出现“按任务而非按 token”定价的 coding agent 套餐；(3) 国内鞋服/电商客户的 AI 代码生成 RFP 会把开放权重模型列为必选项。

DeepSeek V4-Flash-0731 正式公测：仅靠后训练反超 V4-Pro Preview，单任务成本 $0.03

💬 点评

7 月 31 日 DeepSeek 把 V4-Flash 切到正式版，权重未变、只重做后训练（post-training），但官方 9 项 Agent 基准全面跃升：Terminal-Bench 2.1 从 61.8 → 82.7，Cybergym 从 38.7 → 76.7，DeepSWE 从 7.3 → 54.4，Toolathlon-Verified 70.3，全部超过 V4-Pro Preview；价格 $0.14 / $0.28 per M tokens，Artificial Analysis 测算平均任务成本约 $0.03，为已知前沿模型最低。HF 上以 MIT 许可开放权重，下载量一周 10 倍增长。

🎯 业务视角

“换脑不换身”的后训练路线给企业一个强信号：不必每次都重训基座，靠高质量 SFT/RL 数据就能让小激活模型在 Agent 场景反超大旗舰——这直接降低了鞋服客服、供应链、商品中台等内部 Agent 的迭代成本与试错门槛。

🛠 技术背景

激活参数约 13B 级别（远小于 Pro 的 49B），原生适配 OpenAI Responses API，工具调用格式无需转换；社区已在单台 DGX Spark 上以 llama.cpp 跑通 524K 上下文、4 并发 52 tok/s。

🔗 上下游影响

上游推动 Responses API / function-calling 成为事实标准；下游把“Agent 单价 × 成功率”变成新的采购口径，闭源旗舰的 coding agent 溢价被进一步压缩。

🚀 6 个月产品卖点预测

6 个月内：(1) 出现基于 Flash-0731 的“开源 Claude Code 平替”SaaS；(2) 国产 GPU/推理卡的软件适配成为其 ToB 卖点；(3) 企业内部 Agent 的“模型 + 后训练数据”飞轮开始替代“买更强大模型”。

04
蚂蚁 + 人大发布 LLaDA MoE v2：30B-A3B 扩散语言模型仅用 65% 预训练 Token 逼近 Qwen3

💬 点评

8 月 4 日投稿 arXiv 的 LLaDA MoE v2 是“原生 MoE 扩散语言模型（dLLM）”路线的最新里程碑：30B 总参 / 3B 激活，23.5T tokens 从零训练，无需 RL，仅用 Qwen3 30B-A3B 约 65% 的预训练算力就在多项知识/推理/编码基准上逼近 Qwen3；SFT 后在 8 项推理与编码基准中的 7 项超过 SDAR Chat。这是 dLLM 第一次在 30B 量级与主流自回归 MoE 正面对位。

🎯 业务视角

扩散语言模型的并行解码天然适合“可控生成 + 局部改写 + 长文重写”，对营销文案、商品描述、直播脚本这类需要“边写边改”的鞋服电商场景是潜在差异化能力；短期不替换主流 LLM，但应纳入 6–12 个月技术雷达。

🛠 技术背景

核心贡献是 dLLM 专属 scaling law：更大 batch、更快 LR decay、数据侧倾斜；架构上结合 block diffusion 与 MoE 路由；同期 arXiv 2608.01784（REFLEX）提出在 dLLM 中按 refinement 阶段分配 MoE 算力，进一步压低推理成本。

🔗 上下游影响

上游给非自回归推理引擎（如 dLLM 专用 kernel、block diffusion scheduler）创造新需求；下游催生“改写 / 编辑优先”的新一代写作 Agent 与 IDE 插件。

🚀 6 个月产品卖点预测

6 个月内：(1) 主流推理框架会出现 dLLM 专用优化路径；(2) 至少一家国产云厂把 LLaDA 类模型作为“低成本改写”SKU；(3) 营销/电商行业会出现首批基于 dLLM 的“局部重写 + 风格迁移”产品。

ArXiv 三连：LongHorizon-Harness、ContinualSkillBench、Hybrid LLM-RL Agents 重塑长程 Agent 工程范式

💬 点评

本周 arXiv cs.AI / cs.LG 出现三篇方向高度收敛的论文：(1) LongHorizon-Harness（2608.01964）指出把任务状态/完成度塞进不断增长的 context 会让错误自我评估传染，提出外置状态追踪与可验证完成度检查；(2) ContinualSkillBench（2608.03874）用 5 域 × 100 个递进子任务评估 Agent 的“技能库自演化”能力；(3) Hybrid LLM-Augmented RL Agents（2608.03502）让 LLM 出子目标与计划、RL 在环境里精调低层动作，显著提升样本效率与成功率。三者共同把 Agent 从“堆 Prompt + 堆 context”推向“状态外置 + 技能沉淀 + RL 闭环”。

🎯 业务视角

对企业 Agent 项目的可落地性是直接利好：长程任务的成功率与可观测性一直是 PoC 到生产的最大鸿沟，这三篇给出了可复用的工程骨架；鞋服行业的“跨系统补货 / 售后工单 / 营销活动执行”等长流程场景值得优先复用。

🛠 技术背景

关键工程模式：外置 task state store、skill library + 版本化、LLM planner + RL policy 分层、verifier / judge 模型独立于 actor；与 Anthropic《Building Effective Agents》强调的“从简单 workflow 做起”形成互补。

🔗 上下游影响

上游利好 LangGraph / AutoGen / AgentKit 等编排框架增加状态机与 skill 库原语；下游催生“Agent 可观测性 + 轨迹回放 + 技能市场”新品类。

🚀 6 个月产品卖点预测

6 个月内：(1) 主流 Agent 框架会把“外置状态 + skill 库 + verifier”作为默认组件；(2) 出现 Agent 轨迹级 APM 工具；(3) 企业招标会开始要求 Agent 项目提交“状态模型 + 失败恢复设计”。
