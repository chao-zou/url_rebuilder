1. OpenAI 被曝完成超 10 万亿参数模型 Bel 预训练：传为 GPT-6 之后基座，剑指 AGI 阈值

8 月 26 日，科技消息源 @synthwavedd 在 X 平台爆料称，OpenAI 已完成下一代预训练模型，内部代号"Bel"，是前代"Doug"的直接继任者，总参数量超过 10T（10 万亿）。消息称 Bel 将作为 Astra 项目和 GPT-6（经后续 RL 后）的基座，OpenAI 内部期望 Bel 成为"GPT-6 之后的基座模型"，甚至在进一步强化学习后可能成为"AGI 阈值系统"的基础。爆料还称，OpenAI 认为 Anthropic 缺乏足够算力在 2026 年内公开推出能对等回应 Astra 的竞争性模型，可能获得数月领先窗口。此前 8 月初，OpenAI 已透露 Astra 在数学和理论计算机科学的十个长期悬而未决问题上独立取得突破或实质进展，其解决方案已通过 Lean 4 形式化证明助手验证。截至发稿，OpenAI 未官方确认 Bel 的存在或参数规模，该信息仍属未经独立验证的传闻。

💬 点评
10T 参数是一个什么概念？GPT-4 约 1.8T（MoE 总参数），GPT-4o 据传约 1.8T 级别，10T 意味着参数规模跃升 5 倍以上。但需要注意：(1) 这是传闻而非官方确认；(2) "总参数"对 MoE 模型而言不等于激活参数，实际推理成本可能远小于总参数暗示；(3) 参数规模不等于能力——Scaling Law 是否在 10T 级别仍有效，本身就是一个研究问题。更值得关注的信号是 OpenAI 对竞争格局的判断：如果 Anthropic 真的因算力受限无法在 2026 年对等回应，那"算力差距"正在重新成为 AI 竞争的决定性变量。
🎯 业务视角
对企业客户而言，Bel 传闻的短期影响有限——从预训练完成到产品化通常需要 6-12 个月的 RLHF/对齐/安全测试。但中期信号明确：(1) 前沿模型能力可能在 2027 年迎来又一次跃迁，当前基于 GPT-5/Claude 级别构建的 Agent 系统需要预留升级接口；(2) "OpenAI vs Anthropic"的算力差距如果属实，企业在选择长期 AI 合作伙伴时需要考虑供应商的算力可持续性；(3) Astra 在形式化数学证明上的突破意味着高可靠性推理场景（法律、金融、合规）有望受益。
技术背景
Bel 被描述为与 GPT-4.5 "类似规模"但总参数 >10T，这暗示可能采用超大 MoE 架构（总参数大但每 token 激活参数小）。Astra 是 OpenAI 的前沿研究项目，聚焦于自主科学发现和形式化推理。Doug→Bel 的代号序列表明 OpenAI 内部有持续的基座模型迭代管线。Lean 4 验证意味着模型输出可以被机器检查正确性，这是 AI for Math 的关键基础设施。

2. Anthropic MCP 连接器企业托管授权正式 GA：从"逐用户 OAuth"到"组织零接触管控"

8 月 26 日，Anthropic 宣布面向 Claude Team 和 Enterprise 用户的 MCP（Model Context Protocol）连接器企业托管授权功能正式可用。该功能允许组织管理员通过企业身份提供商（IdP）集中配置连接器访问权限，终端用户无需单独进行 OAuth 授权即可自动获得工具和数据访问权限，实现"零接触"（zero-touch）的连接器部署体验。此前，用户每次连接 MCP 工具都需要单独完成 OAuth 授权流程，在大型企业中导致 IT 管理碎片化和权限蔓延风险。企业托管授权将连接器权限纳入组织统一身份治理框架，管理员可以基于角色、部门和最小权限原则集中管控哪些 Agent 可以访问哪些数据源和工具。

💬 点评
这是 MCP 从"开发者协议"走向"企业基础设施"的关键一步。MCP 的核心价值在于标准化 Agent 与外部工具/数据的连接方式，但如果权限管理仍停留在"每个用户自己点授权"，企业 IT 就无法管控 Agent 的数据访问边界。企业托管授权解决了三个问题：(1) 权限可见性——IT 知道哪些 Agent 连了什么；(2) 权限可控性——可以批量授予/撤销；(3) 合规审计——连接器访问纳入企业身份治理。结合上周的 Agent 越界攻击事件，这个功能的时机非常精准。
🎯 业务视角
对企业解决方案团队而言，这是一个强烈的采购信号：MCP 正在成为 Agent 连接的"企业级标准协议"。如果客户已经在使用或评估 Claude Enterprise，MCP 企业托管授权使得将内部系统（CRM、ERP、知识库、数据库）通过 MCP 连接器安全地暴露给 Agent 变得可行。建议：(1) 在 PoC 中展示基于角色的 MCP 连接器权限管控；(2) 对比非 MCP 方案（如逐 API 集成）的权限管理成本；(3) 关注审计日志和合规报告能力。
技术背景
MCP（Model Context Protocol）是 Anthropic 于 2024 年底推出的开放协议，标准化了 LLM/Agent 与外部工具和数据源的连接方式，类似"AI 时代的 USB-C"。企业托管授权在 MCP 协议层面增加了组织身份层，使得 OAuth token 的颁发和管理由企业 IdP 统一控制，而非用户个人授权。支持 SAML/OIDC 等标准企业身份协议。
🔗 上下游影响
上游：MCP 连接器开发者需要适配企业授权模式；中游：企业 IAM/IdP 厂商（Okta、Azure AD、飞书等）可以集成 MCP 权限治理；下游：企业 Agent 部署的安全合规门槛降低，更多内部系统可以安全地接入 Agent。对竞争协议（如 OpenAI Function Calling、Google Extensions）形成标准化压力。

3. DeepSeek V4-Flash-Vision-Exp 上线：视觉与文本同价，每张图仅 384 token，比 GPT-4o 便宜约 30 倍

8 月 21 日，DeepSeek 正式上线多模态视觉理解模型 V4-Flash-Vision-Exp（API ID: deepseek-v4-flash-vision-exp），并在 8 月 25-26 日持续引发开发者社区热议。核心亮点：(1) 视觉能力在所有文本 benchmark 上与 V4-Flash 持平，多模态 Agent 性能官方称接近 Opus-4.8 水平；(2) 图像按尺寸转 token 计费，每张图最多消耗 384 个输入 token，与 V4-Flash 文本完全同价，比 GPT-4o 视觉便宜约 30 倍；(3) 同步发布 Files API 支持免费持久化文件存储，以及 DeepSeek Harness 0.1.1 Agent 框架"开箱即用"；(4) 支持 Chat Completions、Messages 和 Responses 三种 API 端点，允许文本和图像混合输入。模型标注为实验版（Exp），但官方确认已可用于生产环境。

💬 点评
DeepSeek 再次扮演"价格屠夫"角色，但这次的战略意义远超降价本身。视觉理解是 Agent 从"纯文本助手"进化为"能看屏幕、读文档、理解图表"的关键能力。此前多模态 API 的高成本（GPT-4o 每张图约 1000+ token）使得大量"看图"场景（如截图分析、文档 OCR、UI 理解）在规模化部署时成本过高。384 token/图 + 文本同价意味着：(1) 批量图像处理的单位经济学被彻底改变；(2) 多模态 Agent 的"试错成本"大幅降低，可以更频繁地截图、分析、重试；(3) 开源/低成本多模态正在快速追赶闭源前沿。
🎯 业务视角
对鞋服电商等行业，这直接降低了以下场景的 AI 成本：(1) 商品图片理解与标签自动生成（服装款式、颜色、材质、场景识别）；(2) 买家秀/评价图片审核与分类；(3) 竞品截图分析与价格监控；(4) 仓储物流单据/快递面单 OCR；(5) UI 截图自动化测试。建议在 PoC 中对比 DeepSeek V4-Flash-Vision 与 GPT-4o/Gemini Vision 的实际识别准确率和成本，对于准确率要求不极端的场景，DeepSeek 的性价比优势可能是决定性的。
技术背景
V4-Flash-Vision-Exp 基于 V4-Flash 文本模型增加视觉编码器，支持任意尺寸图像输入（自动 resize/patch 化）。384 token/图的上限意味着无论图像分辨率多高，费用都有封顶——这对需要处理高分辨率商品图的场景特别有利。Files API 允许上传文件后在多次请求中复用，避免重复传图的 token 开销。Harness 框架提供了 Agent 工具调用、多步推理和视觉操作的标准化封装。
🔗 上下游影响
上游：迫使 OpenAI、Anthropic、Google 重新评估视觉 API 定价；中游：多模态 Agent 框架（Cline、Dify、Coze等）将快速集成；下游：大量此前因视觉成本受限而无法上线的应用场景（批量图片审核、视频帧分析、UI 自动化）将加速落地。中国多模态模型（Qwen-VL、InternVL、DeepSeek-Vision）形成价格联盟效应。

4. 微软 Project Aion（Copilot OS）泄露：无开始菜单、无桌面、Agent 驱动的"Agent 操作系统"原型

8 月 24-25 日，大量泄露的内部文档和视频揭示了微软一个始于 2024 年或更早的实验性操作系统项目——Project Aion，内部代号"CopilotOS"。该系统基于 Microsoft Edge 浏览器和轻量级 Web3/Win3 代码库构建，完全围绕 Copilot AI 设计：没有传统开始菜单、桌面图标和任务栏，用户界面是一个 Copilot 仪表盘，包含上下文卡片、Web 应用、Microsoft 365 服务和对话窗口。每个对话可以变成一个带自动生成图标的任务专属工作区。系统被描述为"Agent 的 Agent"（agent of agents），可以自主执行任务并调度其他 AI Agent。文档称其为"自动驾驶操作系统"（self-driving OS），可在运行 AOSP、Win3 甚至 Windows 11 的各种新型 AI 专用设备上运行。部分 Aion 的理念后来出现在微软 Build 2026 发布的 Project Solara 中。但微软已于 2026 年 3 月开始减少 Windows 中不必要的 Copilot 入口点，PC 市场下滑 11% 的背景下，Aion 的未来高度不确定。

💬 点评
Project Aion 的泄露价值不在于它是否会成为产品，而在于它揭示了微软对"后应用时代"操作系统的思考：当 AI Agent 可以直接理解用户意图并跨应用执行任务时，"应用图标→点击→操作"的传统交互范式可能被"对话→Agent 编排→结果"取代。这与 xAI Grok Bot 的"零配置、云端 VM、多 Agent 协同"理念异曲同工。但微软的矛盾在于：Windows 的商业根基是 Win32 应用生态，一个不能运行 Win32 应用的"Copilot OS"在 PC 市场萎缩时缺乏商业理由。更可能的路径是 Aion 的 Agent 交互理念渐进式融入 Windows，而非独立成 OS。
🎯 业务视角
对企业 IT 和解决方案团队的启示：(1) "Agent 即界面"正在成为 OS 级趋势，未来的企业软件可能不再是一个个独立应用，而是 Agent 可调度的能力模块；(2) 如果企业系统不提供 Agent 可调用的接口（API/MCP 连接器），在 Agent OS 范式下将变得不可见；(3) 短期内（1-2 年）Windows 仍是主力，但建议新系统设计时预留 Agent 调用接口。对鞋服零售等一线场景，"语音/对话式 Agent 直接操作 POS/库存系统"可能比传统 app 更高效。
技术背景
Aion 使用 Web3/Win3 轻量代码库（非 Win32），Shell 运行在定制版 Edge 中。Agent 运行在策略控制的沙箱环境中，具有对桌面和 Web 应用的范围化访问权限。系统支持跨设备（AOSP/Win3/Windows 11），并通过 Windows 365 连接传统 Windows 应用。"Agent of agents"架构意味着系统级 Agent 可以编排多个子 Agent 完成复杂任务。
🔗 上下游影响
上游：Web 技术栈（Edge/WebView2）在 AI 设备中的重要性提升；中游：企业软件厂商需要提供 Agent 可调用的 API/MCP 接口；下游：用户交互方式可能从"点 app"转向"跟 Agent 说"。竞争层面，Apple Intelligence、Google Gemini 在 OS 层面的 Agent 集成也在加速。

据多家媒体 8 月 25-26 日报道，Google 正在开发名为 Frozen v2 的 AI 专用芯片，其核心思路是将 Gemini 模型架构直接硬编码到硅片中（而非使用通用 TPU 执行软件定义的模型），以减少计算和数据移动开销。据称每瓦可处理的 token 数量比最新通用 TPU 提升 6-10 倍，推理能效和成本效益显著提升。这与 OpenAI Jalapeño（9 个月流片、1.5-1.9 倍性能/瓦超越 Blackwell）形成呼应——超大模型厂正在通过"模型架构-芯片协同设计"系统性降低推理成本。Frozen v2 的定位是推理专用芯片，训练仍依赖通用 TPU。Google 此前已通过 TPU v5/v6 建立了自研芯片能力，Frozen v2 代表了更进一步的"模型即芯片"路线。

💬 点评
"将模型架构硬编码到硅片"听起来激进，但在推理场景中有其合理性：推理时模型结构固定不变（不像训练需要动态调整），将 Transformer 的注意力机制、FFN、MoE 路由等直接做成专用电路，可以大幅消除通用硬件的指令解码、缓存管理等开销。6-10 倍每瓦 token 能力如果属实，将从根本上改变推理经济学。但风险在于：(1) 模型架构演进很快，如果 Gemini 下一代架构变化，硬编码芯片可能很快过时；(2) 通用性差，只能跑特定模型；(3) 芯片设计和制造周期长，可能跟不上模型迭代速度。这更像是 Google 为自家 Gemini 推理构建的"专属引擎"，而非通用解决方案。
🎯 业务视角
(1) 长期趋势明确：超大模型厂正在通过自研芯片将推理成本降到极致，最终惠及使用其 API 的企业客户；(2) 对企业自建 AI 基础设施的启示：通用 GPU 集群适合需要灵活切换模型的场景，但对于固定模型的大规模推理服务，专用芯片的 TCO 优势可能是数量级的；(3) 建议关注"每瓦 token 数"和"每美元 token 数"指标，这比 FLOPS/TOPS 更能反映真实推理经济性；(4) Google Cloud 的 Gemini API 定价可能因 Frozen v2 而获得长期成本优势。
技术背景
"硬编码"通常指将模型的计算图直接映射为硬件电路（类似 ASIC），而非通过通用指令集执行。Frozen v2 可能采用以下技术：注意力机制的专用矩阵乘法单元、MoE 路由的硬件调度、KV Cache 的片上存储优化、低精度（INT4/FP8）固定计算管线。6-10 倍能效提升来自消除通用处理器的指令开销、内存访问优化和模型架构-硬件协同设计。
